# ADR-002: 保持现有 Markdown 编辑器，渐进增强

## Status

Accepted

## Context

当前项目使用 `@uiw/react-md-editor` 作为文章编辑器，该编辑器提供了基础的 Markdown 编辑和预览功能。随着业务发展，需要增强编辑器能力（如工具栏定制、图片拖拽上传、自动保存等）。

## Decision

**短期**：基于现有的 `@uiw/react-md-editor` 进行渐进式增强，满足当前业务需求。

**长期**：在条件成熟时（如需要富文本编辑、协同编辑等高级功能），评估迁移到 Tiptap 或 BlockNote 等现代编辑器。

## Rationale

1. **迁移成本高**：现有编辑器已深度集成到文章创建/编辑流程中，迁移需要修改大量代码和测试用例。
2. **Markdown 对技术博客友好**：技术博客的核心内容是代码片段和技术文档，Markdown 是行业标准格式，对开发者最友好。
3. **当前需求可满足**：通过封装和扩展，现有编辑器可以支持工具栏定制、拖拽上传、自动保存等需求。
4. **避免过度工程**：目前不需要富文本编辑的复杂功能，过早迁移会增加不必要的复杂度。

## Alternatives

| 方案 | 优点 | 缺点 |
|------|------|------|
| 立即迁移到 Tiptap | 功能强大，可扩展性强，支持协同编辑 | 迁移成本高，需要重写编辑器相关代码，Markdown 支持需要额外配置 |
| 迁移到 BlockNote | 块级编辑器，交互体验好 | 同样存在迁移成本，且生态相对较新 |

## Consequences

### 正面

- 无需大规模重构，降低开发风险
- 保持现有用户习惯不变
- 可以分阶段实现功能增强

### 负面

- 工具栏 UI 定制可能受限于现有编辑器的 API
- 某些高级功能（如协同编辑、版本历史）实现困难
- 长期可能仍需面对迁移问题

## 后续计划

1. Phase 2 中封装现有编辑器，添加上传和工具栏增强
2. 持续监控编辑器相关需求的复杂度
3. 若未来出现无法通过扩展满足的需求，启动迁移评估
